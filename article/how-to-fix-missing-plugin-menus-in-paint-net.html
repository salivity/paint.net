How to Fix Missing Plugin Menus in Paint.NET

Plugins expand Paint.NET's functionality with custom effects and file format support, but they may fail to appear in the program's menus after installation. This issue is typically caused by installing files to the incorrect directory, Windows security blocks on downloaded .dll files, failing to extract compressed archives, or running incompatible versions. Following these troubleshooting steps will help you identify the cause and restore your missing plugin menus quickly.

1. Restart Paint.NET

Paint.NET only scans its plugin directories when it launches. If you copied files into the plugin folder while the software was running, the new menus will not appear. Save your current work, close Paint.NET completely, and reopen it.

2. Verify the Installation Directory

Plugins must be placed in the exact directory corresponding to your version of Paint.NET (Classic desktop installer vs. Microsoft Store version) and plugin type:

  • Classic Installer (Default):
    • Effect plugins: C:\Program Files\paint.net\Effects
    • File type plugins: C:\Program Files\paint.net\FileTypes
  • Microsoft Store Version:
    • Effect plugins: Documents\paint.net App Files\Effects
    • File type plugins: Documents\paint.net App Files\FileTypes

Ensure effect plugins are not mistakenly placed in the FileTypes folder or the root Paint.NET directory.

3. Unblock Downloaded DLL Files

Windows often blocks .dll files downloaded from the internet as a security precaution, preventing Paint.NET from loading them.

  1. Navigate to the folder where you installed the plugin.
  2. Right-click the plugin's .dll file and select Properties.
  3. Look at the bottom of the General tab for a security notice that says: "This file came from another computer and might be blocked to help protect this computer."
  4. Check the Unblock box (or click the Unblock button), then click Apply and OK.
  5. Restart Paint.NET.

4. Ensure Files Are Fully Extracted

Paint.NET cannot read plugins directly from .zip, .rar, or .7z archives. If you downloaded a compressed folder, extract its contents before moving them to the Effects directory. Only .dll files (and any accompanying dependency files specified by the creator) should reside directly inside the Effects folder. Avoid leaving plugins inside nested subfolders within Effects.

5. Check Plugin Compatibility and Dependencies

  • Architecture and Paint.NET Version: Newer versions of Paint.NET run on modern .NET runtimes (such as .NET 7 or .NET 8) and are 64-bit only. Outdated plugins that rely on legacy .NET Framework versions or 32-bit architecture may fail to load silently.
  • Additional DLLs: Some complex plugins require secondary dependency files (such as OptionBasedLibrary.dll). Check the plugin creator's installation instructions to confirm whether auxiliary files must be copied alongside the primary plugin.
  • Load Errors Dialog: In Paint.NET, open Settings (gear icon in the top right), navigate to the Plugin Errors tab. If a plugin failed to load due to code errors or missing dependencies, Paint.NET will list the specific error details here.

6. Look Under Alternative Menus

Plugins do not always appear under the specific menu you expect. While most register under Effects, creators can categorize them under submenus like Stylize, Render, Photo, or even their own custom-named submenu. Some tools appear under the Adjustments menu instead of Effects. Use the search function within the Effects menu (available in modern Paint.NET releases) to search for the plugin by name.
