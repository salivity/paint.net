How to Fix Paint.NET Out of Memory Errors

Working with ultra-high-resolution graphics in Paint.NET can quickly exhaust your system resources, triggering disruptive out-of-memory error warnings. This guide explains why Paint.NET runs out of memory when editing massive images and provides immediate, practical solutions to resolve the issue—including managing your undo history, optimizing layer usage, adjusting your canvas size, and increasing Windows virtual memory.

Understand How Paint.NET Uses Memory

Unlike compressed image formats (such as JPEG or PNG) stored on your hard drive, Paint.NET processes images in an uncompressed 32-bit RGBA format in active memory. Every pixel requires 4 bytes of RAM. When working with large images, memory consumption multiplies exponentially based on two factors:

  1. Layers: Each layer duplicates the full uncompressed memory footprint of the canvas, regardless of how much content is on that layer.
  2. History: Paint.NET stores full copies or differential states of your canvas for every action you perform to support unlimited undos.

A single multi-layered image can easily balloon from a few megabytes on disk to tens of gigabytes in RAM.

Flatten Unnecessary Layers

To immediately lower memory usage, merge your layers:

  • Press Ctrl + M to merge a layer down into the one below it.
  • Eliminate empty or redundant layers.
  • Keep only the active elements you are modifying on separate layers, and merge them as soon as you finish adjusting them.

Clear the History Stack

Because Paint.NET retains every stroke and modification in your RAM or temporary scratch directory, a long working session will inevitably trigger memory warnings.

  • Save your work to commit the current progress to disk.
  • Close and reopen the file to flush the active undo history from memory.
  • If you frequently edit massive canvases, make deliberate edits rather than rapid experimental changes that fill the history buffer.

Resize or Tile the Image

If an image exceeds your physical RAM capacity, consider reducing the workload on the software:

  • Reduce DPI or Dimensions: Navigate to Image > Resize (or press Ctrl + R) and lower the resolution to the maximum size required for your output.
  • Work in Segments: Crop the image into smaller, manageable sections using Image > Crop to Selection, edit each segment independently, and stitch them back together once completed.

Increase Windows Virtual Memory (Paging File)

When your physical RAM is exhausted, Windows relies on secondary storage (virtual memory) to prevent application crashes. If your paging file is too small, Paint.NET will immediately report an out-of-memory error.

  1. Press Windows Key + S, type View advanced system settings, and press Enter.
  2. Under the Advanced tab, click Settings in the Performance section.
  3. Select the Advanced tab in the new window, then click Change under Virtual memory.
  4. Uncheck Automatically manage paging file size for all drives.
  5. Select a fast drive (preferably an NVMe or SATA SSD) with sufficient free space.
  6. Select Custom size, set an Initial size matching your current RAM, and set a Maximum size to at least double or triple your physical RAM (e.g., 32,768 MB to 64,000 MB).
  7. Click Set, then OK, and restart your computer.

Close Competing Applications

Ensure that web browsers, video editing suites, and background utilities are closed while editing massive files. Modern web browsers with multiple open tabs can consume gigabytes of memory that Paint.NET requires to allocate large continuous blocks of RAM for raw canvas rendering.
